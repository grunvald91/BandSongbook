# Band Book — утверждённые правила

Здесь **INTENDED STATE**: продуктовые и технические инварианты, утверждённые владельцем. Наличие правила не доказывает его реализацию. **CURRENT STATE** устанавливается отдельно по коду и проверкам среды. Нарушение утверждённого правила — **IMPLEMENTATION GAP**. Найденное агентом, но не утверждённое владельцем правило помечается **CANDIDATE INVARIANT** и не действует как утверждённое требование.

## Группы и данные

1. Данные одной группы не должны попадать в другую.
2. Удалённая сущность не должна самопроизвольно воскресать из старого клиента. Tombstone сохраняет факт удаления до безопасной синхронизации.
3. Клиент не уничтожает неизвестные ему поля лишь потому, что не умеет их отображать или редактировать.
4. Личные настройки музыканта не перезаписываются настройками другого участника.
5. Signed/временный URL аудио не становится постоянным состоянием данных; каноническая ссылка на аудио должна переживать истечение временного URL.
6. Конфликтующие изменения разрешаются предсказуемо, без незаметной потери данных и самопроизвольного воскрешения удалённых сущностей. Простое «последний отправивший полный snapshot затёр всё» не является допустимым конечным межклиентским контрактом. Конкретный алгоритм ещё **не утверждён**.
7. При удалении песни удаляются связанные с ней аудио-привязки и её вхождения в сетлисты. При удалении сетлиста песни общего каталога остаются. Физическое удаление аудиофайла из хранилища **не является утверждённым обязательным механизмом**.
8. Кэширование не должно приводить к показу устаревших или неправильных групповых данных, воспроизведению неправильного аудио либо нарушению корректности синхронизации. Конкретная стратегия кэширования — архитектурное решение; запрет кэшировать определённые URL не установлен как вечное правило.

## Работа музыканта

9. Интерфейс — на русском языке; компактность не делает необходимые элементы управления неудобными и не заслоняет без нужды экран песни.
10. Участник может удобно подключиться к группе по коду или QR.
11. Форматирование текста работает пословно. Не используются невидимые символы/теги, которые нарушают работу курсора, Backspace, отступов или редактирования.
12. При открытой клавиатуре нужные действия форматирования остаются удобно доступны.
13. Показанные текст и песня соответствуют текущему воспроизводимому аудиотреку, в том числе при переключении очереди.

Эти правила не фиксируют конкретные цвета, размеры, форму панели или отдельный макет. Роль owner/admin **не утверждена**.

## CURRENT STATE и IMPLEMENTATION GAP

Android-рабочая копия содержит LWW/tombstone и код сохранения личных настроек (`app/src/main/java/com/fithealthzone/bandsongbook/data/sync/{SyncMerge.kt,SyncRepository.kt}`); Web `feature/prod` отправляет полный снимок (`BandBook-v2/src/sync/SyncProvider.tsx`), сервер заменяет снимок (`sync-server/fastapi_server.py`). В текущем Web service worker исключает sync API и аудио из кэша (`BandBook-v2/public/sw.js`) — это реализация, а не обязательная стратегия на будущее. Эти факты **не подтверждают** соблюдение инвариантов всеми клиентами одновременно. Для каждого установленного расхождения в `ROADMAP.md` указываются проверенный сценарий, затронутые версии и последствия. Неизвестное состояние production остаётся «не подтверждено».

## PENDING — требует отдельного sync-review

Конкретная политика LWW, поведение при равных timestamps, resurrection и совместимость старых клиентов **не утверждены**. До выбора алгоритма нужно проверить Android + Web + server и конфликтные сценарии. Этот pending-вопрос не ослабляет верхнеуровневые правила 2 и 6.

Предполагаемые агентом новые правила до решения владельца обозначаются **CANDIDATE INVARIANT**, а не добавляются в утверждённый список.
